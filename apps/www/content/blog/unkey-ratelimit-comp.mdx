## Unkey vs Upstash: Latency at a Global Scale

For ratelimiting, latency is everything. Developers have to ensure that the controls they put in place don’t become a bottleneck, no matter where the end user is located. High latency translates into noticeable delays and poor user experience, which can lead users to abandon apps or become frustrated during peak periods. With applications serving global audiences, it’s critical that rate limiting does not add any unnecessary round-trip time.

Recent benchmarks show a clear difference between Unkey and Upstash Redis when it comes to latency at scale. Unkey’s infrastructure is designed around a global edge network, which minimizes the distance and number of hops between the user and the rate limiting endpoint. This approach is fundamentally different from traditional Redis-based offerings like Upstash, which often route requests to specific regional clusters, causing latency to spike sharply for users far from those clusters.

To illustrate the real-world impact: when requests are made from Mumbai, Unkey consistently delivers responses in around 10ms, while Upstash takes over 220ms for the same operation. In Frankfurt, Unkey remains below 15ms, while Upstash exceeds 100ms. These differences aren’t theoretical—they reflect actual delays felt by users and downstream services. Across every major region evaluated, Unkey’s global edge platform delivers 5 to 15 times lower latency compared with Upstash Redis, ensuring uniform performance.
